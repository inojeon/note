# 인터랙티브 학습 콘텐츠 작성 가이드

이 가이드는 새 학습 공간에서 노트와 실험을 만드는 사람과 AI가 함께 따를 구현 기준이다. 학습 원본은 `content/`, 공통 표시 기능은 `site/`, 생성 결과는 `public/`로 나눈다. 새로운 실험은 정해진 형식으로 추가하고, 공통 표시 기능을 수정하지 않아도 문서에 들어가야 한다.

현재 공통 실행기와 Hugo 템플릿은 아래 계약으로 실험을 생성한다. 일반 작성과 미리보기에는 Hugo만 필요하며, 자동 검사는 [개발 안내](development.md)의 별도 환경에서 실행한다. 간단한 2D 시작 예시는 `content/experiments/vector-direction/`, 저장 데이터와 3D를 쓰는 예시는 `content/experiments/born-oppenheimer/`다.

## 원본과 표시 기능의 경계

```text
/Users/ino/Projects/2026/note/
├── content/
│   ├── notes/vector/index.md
│   └── experiments/vector-direction/
│       ├── index.md       # 제목, 목적, 조작 안내, 대체 설명
│       ├── view.html      # 실험 화면 조각
│       ├── main.js        # 계산과 상호작용
│       ├── style.css      # 필요한 실험만 추가
│       ├── preview.svg    # 필요한 실험만 추가
│       └── data.json      # 필요한 실험만 추가
├── site/                  # 문서 템플릿, 공통 스타일, 실험 실행기
├── docs/                  # 작성자와 개발자를 위한 가이드
└── public/                # 자동 생성, 직접 수정하거나 커밋하지 않음
    ├── notes/vector/index.html
    └── experiments/vector-direction/index.html
```

실험마다 독립된 폴더를 하나 둔다. 폴더 이름이 안정적인 ID이며 소문자 영문, 숫자, 하이픈을 사용한다. 제목을 바꿔도 ID를 유지한다. 별도 중앙 목록에 중복 등록하지 않는다.

노트에서는 다음 한 줄로 실험을 참조한다.

```markdown
{{< experiment id="vector-direction" >}}
```

공통 템플릿은 ID에 해당하는 실험 원본을 찾아 독립된 HTML 문서를 생성한다. 노트는 이 문서를 `iframe`으로 표시한다. `view.html`의 화면 요소를 노트 본문의 DOM에 직접 섞지 않는다. 같은 실험을 여러 노트에서 사용해도 원본은 하나다.

Hugo의 page bundle은 Markdown과 관련 HTML, 이미지, 데이터 등을 묶을 수 있다. 묶음 안의 `view.html`은 페이지 리소스이므로 실험 템플릿이 명시적으로 읽어 사용한다. 파일을 두는 것만으로 완성된 실험 페이지가 생긴다고 가정하지 않는다. [Hugo page bundles](https://gohugo.io/content-management/page-bundles/), [Hugo page resources](https://gohugo.io/content-management/page-resources/)

| 작성자가 관리하는 것 | 공통 표시 기능이 관리하는 것 |
| --- | --- |
| 학습 목적, 설명, 관찰 질문 | 문서 배치, 검색, 개념 연결 |
| 실험의 그림, 입력 장치, 계산 | 실험 HTML 외곽, 공통 스타일, 로딩 |
| 입력 범위, 단위, 데이터, 근사 조건 | 자산 경로 연결, 테마 전달, 높이 조절 |
| 조작 방법과 실행 없이 읽을 대체 설명 | 실행 실패 표시, 다시 시도, 수명 관리 |

노트나 실험을 추가할 때 사이트 코드에 실험 이름별 분기문을 추가하지 않는다. 새로운 공통 기능이 필요한 경우에만 실행기를 확장한다.

## 실험 설명의 최소 형식

필수 파일은 `index.md`, `view.html`, `main.js` 세 개다. CSS, 데이터, 미리보기 그림은 필요한 경우에만 추가한다. 상호작용이 없는 그림은 노트의 일반 이미지로 넣는다.

`index.md`의 필수 메타데이터는 `title`과 `summary`다. 실험 ID는 폴더 이름에서 얻는다.

```markdown
---
title: "벡터의 방향과 성분"
summary: "길이를 고정하고 방향을 바꾸며 두 성분의 변화를 관찰합니다."
---

## 무엇을 관찰하나요
길이가 1인 평면 벡터의 방향을 바꿀 때 가로와 세로 성분이 어떻게 달라지는지 관찰합니다.

## 조작 방법
방향각 슬라이더를 움직이세요. 범위는 0°부터 360°이며 처음에는 45°입니다.

## 그림 없이 이해하기
0°에서는 성분이 (1, 0), 90°에서는 (0, 1)입니다.
방향이 바뀌어도 두 성분의 제곱합은 1입니다.

## 적용 범위
실수 좌표평면의 단위 벡터를 다룹니다. 일반적인 벡터 공간 전체를 나타내는 모형은 아닙니다.
```

제목 형식은 자유롭게 바꿀 수 있지만, 학습 목적, 조작 방법, 대체 설명, 적용 조건은 빠뜨리지 않는다. 계산 데이터가 있다면 출처와 생성 조건을 적고, 이해를 돕기 위한 예시 값이면 그 사실을 표시한다.

이 Markdown 설명은 실험이 실행되지 않아도 노트에서 읽을 수 있어야 한다. 미리보기 그림을 추가할 때는 설명에 상대 경로로 넣고 대체 텍스트를 작성한다. 공통 렌더러는 이 설명을 노트에 삽입할 때 이미지와 링크를 원래 실험 bundle 기준 URL로 변환한다. 노트 폴더 기준으로 해석하면 안 된다. 별도의 필수 설정 파일이나 메타데이터 목록을 만들지 않는다.

## 화면과 동작 작성 규칙

`view.html`은 화면 조각만 작성한다. `<html>`, `<head>`, `<body>`, `<script>`, `<style>`, `<base>`와 인라인 이벤트 속성은 넣지 않는다. 전체 HTML 구조와 스크립트 연결은 공통 템플릿이 담당한다. 실행 가능한 Hugo 템플릿 코드도 실험 화면에 넣지 않는다.

입력에는 이름과 단위를 표시하고, 값의 범위와 기본값을 HTML에서 명확히 정한다. 실험의 중요한 결과는 그림과 함께 텍스트나 수치로도 보여준다. 하나의 화면에서 ID를 중복 사용하지 않는다.

```html
<div class="experiment" data-experiment-root>
  <label for="angle">방향각 θ (도)</label>
  <input id="angle" data-role="angle"
         type="range" min="0" max="360" step="1" value="45">
  <output data-role="components" aria-live="polite"></output>
  <button type="button" data-role="reset">처음으로</button>
</div>
```

`main.js`는 `mount(root, context)` 함수를 내보낸다. 파일을 import하는 것만으로 실행하거나 다른 화면을 수정하지 않는다. 다음 코드는 실행 계약의 최소 예시이며 완성된 벡터 시각화가 아니다.

```js
export function mount(root, { signal }) {
  const angle = root.querySelector('[data-role="angle"]');
  const output = root.querySelector('[data-role="components"]');
  const reset = root.querySelector('[data-role="reset"]');
  if (!angle || !output || !reset) {
    throw new Error("방향각 실험의 필수 화면 요소가 없습니다.");
  }

  function render() {
    const degrees = angle.valueAsNumber;
    if (!Number.isFinite(degrees) || degrees < 0 || degrees > 360) {
      throw new Error("방향각은 0° 이상 360° 이하이어야 합니다.");
    }
    const radians = degrees * Math.PI / 180;
    const format = value => (Math.abs(value) < 0.0005 ? 0 : value).toFixed(3);
    output.textContent = `${degrees}°: (${format(Math.cos(radians))}, ${format(Math.sin(radians))})`;
  }

  angle.addEventListener("input", render, { signal });
  reset.addEventListener("click", () => {
    angle.value = angle.defaultValue;
    render();
  }, { signal });
  render();
}
```

`context.signal`은 이벤트와 비동기 작업을 정리할 때 사용한다. 데이터 파일의 URL은 공통 실행기가 제공하는 `context.assetURL("data.json")`으로 얻는다. 비동기 초기화가 필요하면 `mount`를 `async` 함수로 작성하고, 첫 화면을 사용할 수 있을 때 완료한다.

애니메이션이나 WebGL 자원을 쓰는 실험은 필요한 경우 `{ setActive(active), destroy() }`를 반환한다. 공통 실행기는 화면 밖이나 비활성 탭에서 `setActive(false)`를 호출하고, 제거하거나 다시 시작할 때 signal을 중단하고 `destroy()`를 호출한다. 사용하지 않는 메서드를 빈 함수로 만들 필요는 없다. 작성자는 일부 초기화 후 실패하거나 취소된 경우에도 signal 처리 또는 예외 처리로 이미 만든 자원을 정리한다.

공통 실행기는 실행마다 식별자를 두고, 재시도·타임아웃·제거 이후 이전 비동기 초기화가 보내는 `ready`를 무시한다. 취소한 초기화가 늦게 완료되면 반환된 `destroy()`도 호출한다. 정리 함수는 여러 번 호출되어도 문제가 없어야 한다.

실험은 자신의 root와 iframe 내부만 다룬다. 부모 문서의 DOM, 스크롤, URL, 전역 상태를 직접 바꾸지 않는다. 부모와의 연결은 공통 실행기에 맡긴다.

## 경로와 의존성

- 이미지와 데이터는 실험 폴더에 두고 상대 경로로 참조한다. 생성된 실험 페이지에서도 그 상대 배치를 보존한다.
- JavaScript가 런타임에 읽는 자산은 `context.assetURL`을 사용한다. 번들링으로 JavaScript 위치가 바뀌어도 데이터 경로가 유지되어야 한다.
- `/assets/...` 같은 사이트 루트 고정 경로, 개발 컴퓨터의 파일 경로, 외부 CDN에 의존하지 않는다. `/note/` 아래 배포를 반드시 지원한다.
- 2D는 SVG나 Canvas를 우선 사용한다. 3D 라이브러리가 필요하면 버전과 라이선스를 고정한 공통 로컬 자산을 필요한 실험에서만 사용한다.
- 실험마다 npm 프로젝트나 별도 빌드 체계를 만들지 않는다. 일반 작성과 미리보기는 Hugo와 브라우저로 한다.
- 실행 대상은 로컬 HTTP 서버와 공개 웹이다. 생성 HTML을 `file://`로 더블클릭하는 실행 방식은 지원 범위에 포함하지 않는다.

공유 로컬 라이브러리가 필요한 실험은 설명 파일의 선택적 `params.scripts`에 사이트 기준 상대 경로를 적는다. 예를 들어 보른–오펜하이머 실험은 다음 설정으로 로컬 3Dmol.js를 사용한다.

```yaml
params:
  scripts: ["vendor/3dmol/3Dmol-min.js"]
```

공통 2D 도구가 필요하면 `main.js`에서 `experiment-shared.js`를 정적 import할 수 있다. 공유 도구는 `site/assets/experiment-shared.js`에 있으며, 실험마다 외부 패키지를 설치하지 않는다. 새 라이브러리는 버전·라이선스와 필요한 기능을 확인한 뒤 공통 로컬 자산으로 관리한다.

JavaScript는 Hugo의 `js.Build`를 통해 처리해 문법 오류와 해결할 수 없는 정적 import를 빌드 때 확인한다. 이 기능은 Hugo 안의 esbuild를 사용한다. 사용 버전은 로컬과 CI에서 고정하고 페이지 리소스의 import 해석도 대표 실험으로 검증한다. 임의의 동적 import 경로는 만들지 않는다. [Hugo js.Build](https://gohugo.io/functions/js/build/)

## 실험 화면의 수식

Markdown 설명의 수식과 `view.html`의 고정 수식은 Hugo가 빌드할 때 처리한다. 화면 조각에서는 다음처럼 TeX 원문을 표시한다.

```html
<span class="math-tex" data-tex="x^2+y^2=1"></span>
```

슬라이더 조작에 따라 수식 자체가 바뀌는 실험만 `index.md`에 다음 항목을 넣는다.

```yaml
params:
  dynamic_math: true
```

이 실험 페이지에만 로컬 KaTeX JavaScript와 수식 관찰기가 연결된다. 동작 코드에서는 `.math-tex[data-tex]` 요소의 `dataset.tex`를 바꾸면 된다. 일반 본문 전체를 다시 훑거나 외부 수식 CDN을 불러오지 않는다. 고정 수식만 있는 실험에는 이 옵션이 필요하지 않다. 잘못된 동적 수식은 실행 오류이므로 대표 입력과 경계값에서 확인한다.

iframe 안에도 공통 스타일을 로드한다. 부모 문서의 CSS 변수가 iframe에 자동으로 상속된다고 가정하지 않는다. 시스템 테마와 직접 고른 테마를 모두 확인하며, 실험을 따로 연 페이지에서도 같은 대비를 유지한다. 브라우저 뒤로가기로 복원된 실험은 다시 조작할 수 있어야 한다.

## 공통 표시 기능이 보장할 동작

iframe은 실험과 본문의 문서 구조 및 스타일을 분리하는 용도로 사용한다. 첫 버전은 같은 사이트에서 제공하는 작성자 소유 실험을 대상으로 한다. iframe이 무한 반복의 CPU 영향이나 모든 오류를 차단한다고 보장하지 않는다. [MDN iframe](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe)

1. 실험 영역에 제목, 설명, 선택적 미리보기 그림을 먼저 출력한다. 이 내용은 iframe 밖에 둔다. JavaScript가 꺼져도 설명이 남고 인쇄에도 포함된다.
2. 화면 가까이에 온 실험을 불러온다. 초기 영역 높이를 확보해 본문이 갑자기 밀리는 현상을 줄인다.
3. 공통 실행기가 모듈 import와 `mount`를 수행한다. 완료 후 보내는 `ready` 신호를 받아야 실행 성공으로 판단한다.
4. import 실패, 초기화 실패, 처리되지 않은 실행 오류는 해당 실험의 오류 상태로 표시한다. 실패 시 중단 신호와 자원 정리를 수행하고 iframe을 제거한다. 대체 설명과 다시 시도 버튼은 유지하고, 재시도는 새 iframe과 실행 상태로 시작한다. 작성자에게는 원인과 실험 ID를 남긴다.
5. 제한시간은 부모가 실제 로딩을 시작한 시점부터 잰다. 화면 밖에서 기다리는 실험에 타임아웃을 적용하지 않는다.
6. 높이 변경은 내용 크기를 기준으로 보고하며 부모는 유한한 값과 허용 범위를 검사한다. 과도한 높이는 프레임 내부 스크롤로 처리하고 본문 전체 크기를 변경하지 않는다. 높이 측정에 프레임 높이 의존 값을 사용해 무한 확대되는 순환을 만들지 않는다.
7. 같은 실험을 두 번 삽입해도 상태와 메시지를 각각 구분한다. iframe의 `title`은 실험 이름으로 설정한다. 단독 페이지로 열어 확인할 수 있는 링크도 제공한다.

iframe의 `load` 이벤트는 로딩 실패에도 발생할 수 있으므로 성공 신호로 사용하지 않는다. 부모와 실험의 메시지는 보내는 출처, 해당 iframe의 window, 허용한 메시지 종류와 값 형식을 함께 확인한다. 이런 통신은 공통 실행기에서 한 번 구현한다. [MDN iframe 이벤트](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe#error_and_load_event_behavior), [MDN postMessage](https://developer.mozilla.org/en-US/docs/Web/API/Window/postMessage)

## 완료와 공개의 기준

작성 완료는 원본 파일 생성, 빌드, 실제 브라우저 확인까지를 뜻한다. Hugo 빌드 성공만으로 화면과 계산의 정확성을 보장하지 않는다.

| 단계 | 확인할 내용 | 실패 시 처리 |
| --- | --- | --- |
| 작성 검토 | 목적, 조작 방법, 대체 설명, 적용 조건의 실제 내용 | 빠진 설명을 보완한다. 제목이나 문장 의미까지 자동 판정한다고 가정하지 않는다. |
| Hugo 빌드 | 실험 ID, 필수 파일과 메타데이터, 비어 있지 않은 설명 본문, 알려진 자산 참조, JavaScript 문법과 정적 import | 오류가 있는 노트 또는 실험 ID와 원본 경로를 출력하고 배포 빌드를 중단한다. |
| 브라우저 검사 | 실험 ready, 실제 입력 조작과 예상 결과, 콘솔 오류, 자산 요청 실패, 화면 넘침 | 수정 전까지 배포하지 않는다. |
| 실패 상황 검사 | JS 로드 실패, 데이터 로드 실패, 초기화 오류, WebGL 미지원 시 본문과 대체 설명 보존 | 공통 실행기의 회귀 검사로 유지한다. |
| 배포 경로 검사 | 로컬 루트와 `/note/` 하위 경로에서 동일한 동작 | 잘못된 경로를 고친 뒤 다시 검사한다. |

브라우저 검사는 검증용 CI에서 수행하고 평소 노트 작성자의 필수 설치에 포함하지 않는다. 기본은 고정 버전의 Playwright와 Chromium으로 검사한다. 공통 화면이나 3D 기능을 바꾸는 릴리스는 WebKit과 실제 모바일 화면 확인도 포함한다. 검사에 통과한 생성 결과를 그대로 공개한다.

모든 실험은 대표 조작과 기대 결과를 설명에 명시한다. 새 계산 로직에는 정상값, 경계값, 정의되지 않는 입력에 대한 의미 있는 검사를 추가한다. 단순히 버튼의 존재나 구현식 자체를 복제하는 검사로 대체하지 않는다.

벡터 방향 실험의 기준은 다음과 같다.

- 0°에서 `(1, 0)`, 90°에서 `(0, 1)`, 180°에서 `(-1, 0)`에 가까워야 한다.
- 방향을 바꿔도 계산한 성분의 제곱합은 1이어야 한다. 내부 수치는 예를 들어 `1e-6` 허용 오차로 비교하고 화면 표시는 표시 자릿수에 맞춘다.
- 초기화 후 기본 각도와 화면이 함께 복원되어야 한다.
- 같은 노트에 두 번 삽입한 경우 한쪽 조작이 다른 쪽 값을 바꾸면 안 된다.
- 모바일 폭과 키보드 조작에서도 동일한 결과를 얻어야 한다.

## AI와 함께 만드는 순서

1. 관찰할 개념, 바꿀 입력, 기대하는 결과, 적용 조건을 먼저 정한다.
2. 공통 실험 템플릿을 바탕으로 원본 폴더를 만든다. 설명과 실제 동작을 함께 작성한다.
3. 노트에 실험 ID를 참조하고 빌드 오류를 해결한다.
4. 생성된 HTML을 브라우저에서 열어 대표 조작과 계산 결과를 검증한다.
5. 좁은 화면과 실패 시 대체 표시를 확인한다.
6. 사용자는 학습 화면을 보고 수정을 요청한다. AI는 원본을 고치고 다시 생성한다.

실험 작성 때마다 실행기와 오류 처리를 새로 만들지 않는다. 기존 벡터 방향과 보른–오펜하이머 실험을 각각 2D·3D 참고 예시로 사용하되, 입력 범위·계산·설명·기대 결과는 새 학습 목적에 맞게 함께 바꾼다.

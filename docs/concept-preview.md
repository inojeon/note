# 본문 개념 미리보기 작성 규칙

본문의 개념 링크는 제목·요약과 짧은 예시·수식을 보여주는 미리보기 카드로 연결된다. 이 문서는 현재 공통 렌더러와 브라우저 기능에 맞춘 작성 규칙이다. 기본 노트 작성은 [노트 작성 가이드](note-authoring.md)를 따른다.

## 원본과 작성 방법

노트 작성자는 일반 Markdown 링크로 설명이 필요한 개념을 표시한다.

```markdown
벡터는 선택한 [기저](../basis/)에 따라 다른 성분으로 표현할 수 있습니다.
```

렌더러는 내부 개념 노트로 향하는 링크를 찾아 미리보기를 연결한다. 외부 링크, 일반 파일 링크, 코드 블록, 수식 안의 단어는 대상으로 삼지 않는다. 이 링크는 개념 연결과 역방향 링크 생성에도 함께 사용한다.

제목과 짧은 설명은 대상 노트의 `index.md`에 있는 `title`, `summary`를 사용한다. 별도 용어 사전에 같은 정의를 다시 작성하지 않는다. 짧은 예시나 수식이 필요하면 대상 노트 옆에 선택적인 `preview.md`를 둔다.

```text
/Users/ino/Projects/2026/note/content/notes/basis/
├── index.md       # 제목, 요약, 상세 설명의 원본
└── preview.md     # 선택 사항: 미리보기에 덧붙일 짧은 예시와 수식
```

미리보기는 제목, 요약, 선택적 예시, 개념 노트 읽기 링크로 구성한다. 원래 링크의 query와 섹션 주소가 있다면 상세 읽기 링크에서도 유지한다. `preview.md`가 없으면 제목과 요약만으로 동작한다. 예시에는 짧은 글과 수식을 허용하고, 중첩 팝오버나 실행 가능한 실험은 넣지 않는다. 문서별 툴팁 HTML이나 스크립트를 작성하지 않는다.

동음이의어와 한국어 부분 단어를 잘못 연결하지 않도록 본문의 모든 일치 단어를 자동 치환하지 않는다. AI가 글을 작성할 때 필요한 첫 등장 또는 새 문맥의 용어를 링크로 표시한다. 미리보기를 연결하기 위해 원본 Markdown을 빌드 중 수정하지 않는다.

대상 노트의 이미지를 미리보기에서 사용하는 경우 원래 대상 노트의 bundle 기준으로 URL을 해석한다. 수식은 본문과 같은 빌드 시 렌더링을 사용한다.

## 공통 화면의 동작

- 데스크톱에서는 마우스를 올리거나 키보드 초점을 주면 개념 설명을 미리 보여준다. 마우스를 설명 카드로 옮겨도 닫히지 않는다.
- 용어를 클릭하거나 터치하면 설명을 유지하고 카드 안의 개념 노트 읽기로 이동할 수 있게 한다. 닫기 버튼, Escape, 바깥 클릭으로 닫을 수 있다.
- JavaScript 초기화 전이나 실행 실패 시에는 원래 개념 링크로 이동할 수 있다. 미리보기 초기화에 성공한 경우에만 트리거를 버튼으로 바꾸고 상태를 연결한다.
- 키보드로 트리거를 활성화하고 카드 안의 링크와 닫기 버튼에 접근할 수 있어야 한다. 명시적으로 연 카드를 닫을 때는 열었던 트리거로 초점을 돌려준다. 마우스 hover만으로 초점을 강제로 옮기지 않는다.
- 카드의 마지막 링크에서 Tab을 누르면 카드를 닫고 원래 용어 다음의 본문 조작 요소로 이어간다.
- 읽는 도중 자동으로 사라지지 않으며 한 번에 한 카드만 연다. Escape로 닫은 직후 동일한 hover나 focus 때문에 바로 다시 열리지 않게 한다.
- 카드가 모바일 화면 밖으로 나가거나 본문 폭을 늘리지 않도록 배치한다. 긴 내용은 카드 내부에서 스크롤할 수 있게 한다.
- 화면 변경이나 페이지 이동 때 열려 있는 카드를 정리한다. 같은 개념이 여러 번 등장해도 트리거와 카드 ID가 충돌하지 않아야 한다.

링크와 닫기 버튼을 포함하므로 단순한 `role="tooltip"`을 붙이는 대신 키보드 조작이 가능한 비모달 팝오버로 구현한다. hover와 focus로 나타나는 내용은 닫을 수 있고, 마우스를 그 내용 위로 옮길 수 있으며, 읽는 동안 유지되어야 한다. [W3C hover와 focus 콘텐츠 기준](https://www.w3.org/WAI/WCAG22/Understanding/content-on-hover-or-focus.html), [W3C tooltip 패턴](https://www.w3.org/WAI/ARIA/apg/patterns/tooltip/)

## 검증 기준

- 존재하지 않는 내부 개념 대상, 필수 제목과 요약 누락, 잘못된 수식은 빌드에서 발견한다. 작성자는 요약의 정확성과 예시의 적절성을 검토한다.
- 대상 노트의 요약을 수정하고 다시 빌드하면 참조하는 모든 미리보기에 반영되어야 한다.
- 브라우저에서 hover, 키보드, 터치 열기, 닫기, 상세 노트 이동을 확인한다. 트리거에서 카드로 포인터나 키보드 초점을 옮기는 동안 카드가 유지되어야 한다.
- 좁은 화면, 화면 가장자리, 스크롤 후 위치, 밝은 테마와 어두운 테마를 확인한다.
- JavaScript 비활성 및 미리보기 초기화 실패에서도 원래 개념 노트 링크를 사용할 수 있어야 한다.
- 로컬 루트와 `/note/` 배포 경로에서 대상 링크와 수식, 선택적 이미지가 정상 표시되어야 한다.

기존 동작의 참고 원본은 `references/sqd-docs/tools/enrich_concepts.py`, `references/sqd-docs/docs/assets/concept-glossary.js`, `references/sqd-docs/docs/assets/concept-glossary.json`이다. 새 구현은 원본 HTML을 직접 고쳐 팝오버를 삽입하던 과정을 사용하지 않고 공통 렌더러에서 생성한다.

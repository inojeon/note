PySCF로 SQD 입력 만들기
질소 분자 N₂ 예제

양자컴퓨터가 돌기 전에 고전 컴퓨터가 해야 하는 준비 작업을 PySCF 코드와 함께 따라갑니다. 문서의 숫자는 모두 PySCF로 실제 계산한 값입니다.

SQD 함수는 hcore, eri, norb, nelec 네 가지를 요구합니다. 이 문서는 "분자 이름"에서 출발해 그 네 가지가 나오기까지의 절차입니다.

한눈에 보기

예제 분자: N₂

질소 분자를 예로 잡은 이유는 세 가지입니다. 원자 둘뿐이라 그리기 쉽고, 두 원자가 삼중결합으로 묶여 있어 전자 상관이 강하며, SQD 원 논문의 첫 벤치마크 분자이기도 합니다.

from pyscf import gto, scf, mcscf, ao2mo

mol = gto.M(
    atom="N 0 0 0; N 0 0 1.098",   # 원소 기호와 x y z 좌표 (Å)
    basis="cc-pvdz",                 # 기저 세트
    spin=0, charge=0,                # 짝수 전자, 중성
)
print(mol.nelectron)   # 14
print(mol.nao)         # 28  ← 궤도(기저함수) 수

1. 기저 선택: 궤도 수가 정해진다

기저는 원자마다 전자 구름을 표현할 블록을 몇 개 줄지 정하는 선택입니다. N 원자 하나에 주어지는 블록 수가 세트마다 다르고, 분자 전체의 궤도 수는 그 합입니다.

기저N 원자당 함수N₂ 궤도 수HF 에너지 (Ha)용도
sto-3g510−107.496알고리즘 테스트, 손 검산
6-31g918−108.868빠른 정성적 계산
cc-pvdz1428−108.954무난한 기본값
cc-pvtz3060(계산 생략)정량적 비교

2. Hartree-Fock: 궤도 모양이 정해진다

기저가 블록을 깔아 주면, HF는 그 블록들을 어떤 비율로 섞어야 분자 궤도가 되는지 찾습니다. 각 전자가 나머지 전자들의 평균 구름만 보는 근사로, "구름 추측 → 전자 하나씩 풀기 → 구름 갱신"을 수렴할 때까지 반복합니다.

mf = scf.RHF(mol).run()
# converged SCF energy = -108.954087
print(mf.mo_energy.shape)   # (28,)  궤도 에너지
print(mf.mo_coeff.shape)    # (28, 28)  열 = 궤도 하나, 행 = 기저함수 계수
print(mf.mo_occ)            # [2 2 2 2 2 2 2 0 0 ... 0]  낮은 7개에 전자 2개씩

결과를 에너지 순으로 세우면 N₂의 궤도 사다리가 나옵니다. 아래는 cc-pVDZ 계산에서 실제로 나온 에너지입니다.

HF 에너지 −108.954 Ha는 참값에서 약 0.4 Ha(약 0.4%) 위에 있습니다. 작아 보여도 N₂ 삼중결합 에너지 전체가 그 안에 들어가므로, HF만으로는 결합을 설명할 수 없습니다. 이 차이가 전자 상관이고, SQD가 되찾으려는 것입니다.

3. 활성 공간: norb와 nelec이 정해진다

28개 궤도를 모두 양자컴퓨터에 올리면 큐비트 56개가 필요합니다. 그럴 필요가 없는 이유는, 궤도 대부분이 "결과가 뻔한" 자리이기 때문입니다.

층N₂ cc-pVDZ에서처리
내각 (core)1s 궤도 2개, −15.7 Ha항상 꽉 참 → 상수 에너지 ecore로 흡수
활성 (active)2s·2p에서 온 궤도 8개전자 10개가 어떻게 배치될지 → SQD가 푸는 문제
가상 (virtual)나머지 18개, +0.6 Ha 이상항상 빔 → 무시
ncas, nelecas = 8, (5, 5)          # 활성 궤도 8개, 활성 전자 α5 β5
cas = mcscf.CASCI(mf, ncas, nelecas)
# 기본값: HF 궤도 중 내각 2개를 건너뛰고 그 위 8개를 활성으로 잡음
# (ncore = (14 - 10) // 2 = 2 를 PySCF가 자동 계산)

이 선택이 SQD 함수의 norb=8, nelec=(5,5)가 됩니다. 큐비트는 2×8 = 16개입니다. 어디서 자를지는 자동이 아니라 판단입니다. 결합 끊김을 보려면 결합·반결합 궤도 쌍이 모두 활성에 들어가야 하고, 이 예의 8개는 N₂의 2s·2p 원자가 궤도 전부를 포함하는 "완전 원자가 활성 공간"이라 표준적인 선택입니다.

4. 적분 텐서: hcore와 eri

활성 궤도가 정해지면, 그 궤도들 사이에서 가능한 모든 전자 움직임의 에너지를 미리 계산해 표로 만듭니다. 전자는 쌍으로만 상호작용하므로 1전자 표와 2전자 표, 두 장이면 전체 에너지를 조립할 수 있습니다.

hcore, ecore = cas.get_h1eff()               # (8, 8), 그리고 내각 에너지 상수
eri = ao2mo.restore(1, cas.get_h2eff(), ncas)   # (8, 8, 8, 8)
print(ecore)                                 # -77.417423  (핵 반발 + 내각 전자 에너지)

정리: SQD 입력 네 가지의 정의

네 단계를 거치며 SQD 함수의 네 인자가 모두 나왔습니다. 정수 둘은 문제의 크기를, 배열 둘은 에너지 규칙을 담습니다.

인자모양한 줄 정의N₂ 예제
norbint활성 궤도 수 = 전자가 앉을 자리 수8
nelec(int, int)활성 전자 수를 (α, β)로 나눈 것(5, 5)
hcore[norb, norb]전자 하나의 에너지 가격표8×8
eri[norb, norb, norb, norb]전자 둘의 밀어냄 가격표8×8×8×8

크기를 정하는 둘: norb, nelec

norb는 1단계(기저)에서 만든 궤도를 3단계(활성 공간)에서 잘라 남긴 개수입니다. 큐비트는 궤도당 둘(α, β)이라 2·norb개. nelec은 원자 번호 합에서 charge와 내각 전자를 빼고 spin으로 α·β를 나눈 것입니다. N₂: 7+7 = 14, 내각 4개 제외 → 10, spin=0 → (5, 5). 이 두 수가 2절 비트열의 길이(2·norb)와 각 절반의 1 개수(nelec)를 정합니다.

에너지를 정하는 둘: hcore, eri

왜 두 장이면 충분한가. 분자의 에너지는 두 종류뿐입니다. 전자 혼자서 생기는 것(핵에 끌림, 운동에너지)과 전자 둘이 만나서 생기는 것(서로 밀어냄). 쿨롱 힘은 항상 둘 사이에서만 작용하므로 셋 이상이 얽히는 항은 없고, 전자가 몇 개든 가격표 두 장으로 에너지를 조립할 수 있습니다.

왜 그 모양인가. 전자는 한 자리에 머물지 않고 옮겨 다니므로, 가격표에는 "머물 때" 값뿐 아니라 "어디서 어디로 옮길 때" 값도 있어야 합니다. 그래서 인덱스는 전자 하나당 출발·도착 둘씩입니다.

표인덱스뜻칸 수 (궤도 3개)칸 수 (N₂, 8개)
hcore[i,k]i, k전자가 i에서 k로3² = 98² = 64
eri[i,j,k,l]i, j, k, l전자 A가 i→k, 전자 B가 j→l3⁴ = 818⁴ = 4,096

eri는 앞의 (i, j)를 고정하면 뒤의 (k, l)이 판 하나를 이루므로, "norb×norb 판이 norb² 장" 쌓인 구조로 보면 쉽습니다. 궤도 3개면 3×3 판 9장, N₂면 8×8 판 64장입니다.

어떻게 쓰는가. 배치가 정해지면 해당 칸을 골라 더합니다. 아래는 궤도 3개짜리 축소판으로, 실제 텐서와 같은 모양입니다.

이 네 가지로 무엇을 하나

대각화할 큰 행렬의 모든 칸 H[A,B]는 위 방식으로 두 표에서 조립되고, 양자 회로의 게이트 각도도 두 표에서 계산됩니다. 분자의 화학 정보는 이 네 가지로 전부 숫자화되며, 그 뒤 단계는 분자가 무엇인지 몰라도 똑같이 돌아갑니다.

왜 HF로 끝나지 않나: 결합을 늘려 보기

평형 거리에서 HF와 정확한 답의 차이는 0.08 Ha입니다. 그런데 결합을 늘리면 이 차이가 급격히 벌어집니다. 두 원자가 멀어질수록 "전자가 어느 원자에 있는가"가 애매해져서, 하나의 배치로 표현하는 HF가 무너지고 여러 배치를 섞어야만 맞는 답이 나오기 때문입니다.

5. SQD로 넘기기

이제 네 가지가 모두 준비되었습니다. 양자 회로 쪽(비트열 생성)은 별도 단계이므로 여기서는 입력이 어떻게 대응되는지만 봅니다.

from qiskit_addon_sqd.fermion import diagonalize_fermionic_hamiltonian

result = diagonalize_fermionic_hamiltonian(
    hcore,                 # 4단계: (8, 8)
    eri,                   # 4단계: (8, 8, 8, 8)
    bit_array,             # 양자 회로 측정 결과, 길이 16 비트열들
    samples_per_batch=300,
    norb=ncas,             # 3단계: 8
    nelec=nelecas,         # 3단계: (5, 5)
    num_batches=5,
    max_iterations=10,
)
energy = result.energy + ecore   # 활성 공간 에너지에 내각 상수를 더해야 전체 에너지

ecore를 빼먹는 것이 가장 흔한 실수입니다. SQD가 돌려주는 에너지는 활성 공간 안의 전자 10개 에너지뿐이고, 내각 전자 4개와 핵 반발 에너지(−77.42 Ha)는 따로 더해야 CASCI나 실험값과 비교할 수 있습니다.

작게 검증하기

양자컴퓨터 없이도 이 입력이 올바른지 확인할 수 있습니다. 활성 공간이 작으면 CASCI가 정확한 답을 주므로, SQD에 "완벽한 샘플"을 넣었을 때 같은 값이 나오는지 보면 됩니다.

e_casci = cas.kernel()[0]          # -109.034407 (전체 에너지, ecore 포함)
# SQD 결과: result.energy + ecore 가 이 값에 가까워야 함
# 샘플이 충분하면 1e-3 Ha 이내, 완벽하면 1e-8 Ha 이내

전체 코드

from pyscf import gto, scf, mcscf, ao2mo

# 1. 분자와 기저 → 궤도 수
mol = gto.M(atom="N 0 0 0; N 0 0 1.098", basis="cc-pvdz")

# 2. Hartree-Fock → 궤도 모양, 기준 배치
mf = scf.RHF(mol).run()

# 3. 활성 공간 → norb, nelec
ncas, nelecas = 8, (5, 5)
cas = mcscf.CASCI(mf, ncas, nelecas)

# 4. 적분 텐서 → hcore, eri, ecore
hcore, ecore = cas.get_h1eff()
eri = ao2mo.restore(1, cas.get_h2eff(), ncas)

# 검증용 정확한 답 (작은 활성 공간에서만 가능)
e_exact = cas.kernel()[0]

print(f"norb={ncas} nelec={nelecas} hcore{hcore.shape} eri{eri.shape}")
print(f"E_HF={mf.e_tot:.6f}  E_CASCI={e_exact:.6f}  ecore={ecore:.6f}")
# norb=8 nelec=(5, 5) hcore(8, 8) eri(8, 8, 8, 8)
# E_HF=-108.954087  E_CASCI=-109.034407  ecore=-77.417423

마무리: 비전공자는 어디까지 알아야 하나

목표가 "SQD 코드를 돌리고 구조를 이해한다"라면 필요한 화학 지식은 생각보다 적습니다. 이 문서에 나온 내용을 두 단계로 나누면 다음과 같습니다.

반드시 알아야 하는 것 — 코드를 읽는 데 필요

  • 배치(configuration) = 전자를 궤도에 넣는 한 가지 방법 = 비트열 하나. SQD의 기본 단위.
  • 비트열 규약: 왼쪽 절반 β, 오른쪽 절반 α. 각 절반의 1 개수가 그 스핀의 전자 수.
  • norb, nelec은 문제의 크기, 큐비트 수는 2·norb. hcore, eri는 그 크기에 맞는 에너지 가격표이며 안의 개별 숫자를 이해할 필요는 없음.
  • 측정 빈도 ≈ 진폭 제곱. 자주 나오는 비트열이 중요한 배치.
  • 양자컴퓨터는 후보 목록만 만들고, 에너지는 고전 대각화가 구함.
  • 전자 수가 안 맞는 비트열은 잡음. 후선별과 복구의 근거는 nelec.

이 정도면 diagonalize_fermionic_hamiltonian의 모든 인자가 무엇인지, 각 모듈이 왜 있는지 설명할 수 있습니다.

알면 좋은 것 — 입력을 직접 만들거나 결과를 해석할 때

  • 기저 = 원자당 블록 수, 활성 공간 = 궤도 자르기. 둘이 합쳐져 norb를 정함.
  • HF = 평균장 근사. 출발점이지 답이 아님. 기준 배치(0011|0011 류)의 출처.
  • charge → 전자 수, spin → α/β 개수. 틀리면 오류 없이 다른 문제를 풀어 버림.
  • ecore를 더해야 전체 에너지. 활성 공간 에너지만으로는 실험값·CASCI와 비교 불가.
  • 상관 에너지가 커지는 상황(결합 늘리기, 전이금속)이 HF로 부족하고 SQD가 필요한 이유.

비전공자가 막히는 지점은 보통 화학이 아니라 "이 숫자가 어디서 와서 어디로 가는가"입니다. 맨 위의 파이프라인 그림처럼 데이터 흐름을 붙잡고 있으면, 화학 지식은 필요한 만큼만 나중에 채워도 됩니다.

PySCF 문서: pyscf.org · 이 문서의 수치는 PySCF 2.x, cc-pVDZ, N–N 1.098 Å에서 계산했습니다. 다른 버전에서는 마지막 자리가 다를 수 있습니다.

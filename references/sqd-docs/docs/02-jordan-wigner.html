문서 2 / 6

궤도를 큐비트로
Jordan–Wigner 변환

문서 4에서 "ffsim이 알아서 한다"고 넘어간 대응을 한 겹 더 엽니다. 전자 문제가 어떻게 큐비트 문제가 되는지, 비트열 규약이 왜 그 모양인지, 그리고 SQD 코드 어디에서 이 변환이 등장하는지. 숫자는 N₂(활성 8궤도)와 H₂(2궤도) 실제 계산값입니다.

전자가 "있다/없다"를 큐비트의 |1⟩/|0⟩에 대응시키는 것이 전부입니다. 나머지는 전자가 서로 자리를 바꿀 때 생기는 부호를 큐비트로 흉내 내는 장치입니다.

한눈에 보기

1. 점유 수 = 비트

궤도 i에 α 전자가 있는지는 0 또는 1, β 전자가 있는지도 0 또는 1입니다. 이 두 "자리"를 스핀 궤도라 부르고, 궤도 8개면 스핀 궤도 16개입니다. 스핀 궤도 하나를 큐비트 하나로 쓰면 전자 배치 하나가 16비트 문자열 하나와 정확히 일대일로 대응합니다.

스핀 궤도큐비트 번호 (ffsim 규약)비트열에서의 위치
α, 궤도 pp (0~7)오른쪽 절반, 오른쪽에서 p번째
β, 궤도 p8 + p (8~15)왼쪽 절반, 오른쪽에서 p번째

Qiskit은 비트열을 큐비트 번호가 큰 쪽부터 출력합니다. 그래서 큐비트 15~8(β)이 왼쪽, 7~0(α)이 오른쪽에 찍히고, 문서 6의 규약 [b_7…b_0 | a_7…a_0]이 나옵니다. 규약은 "약속"이 아니라 이 번호 매기기의 결과입니다.

2. 2궤도 장난감: H₂

궤도 2개, 전자 α1·β1이면 큐비트 4개입니다. 가능한 비트열 16개 중 전자 수가 맞는 것은 4개뿐이고, SQD의 후선별이 거르는 것이 나머지 12개입니다.

3. 전자 연산 → 큐비트 연산

hcore와 eri의 각 칸은 "전자를 i에서 빼서 k에 넣는다" 같은 연산에 붙는 계수였습니다. 이 연산을 큐비트로 옮기면 "큐비트 i를 1→0으로, 큐비트 k를 0→1로"가 되고, 이는 X와 Y 게이트의 조합으로 쓸 수 있습니다.

전자 연산뜻큐비트 연산 (부호 장치 제외)
a†kk에 전자 넣기 (0→1)(Xk − iYk)/2
aii에서 전자 빼기 (1→0)(Xi + iYi)/2
a†iaii에 전자가 있는지 세기(I − Zi)/2
a†kaii → k 이동 (hcore[i,k]에 붙음)위 둘의 곱 + Z 사슬

세 번째 줄이 가장 직관적입니다. Zi는 |0⟩에 +1, |1⟩에 −1이므로 (I − Z)/2는 |0⟩에 0, |1⟩에 1을 줍니다. 즉 "전자 수 세기"가 Z 게이트 하나입니다. hcore의 대각 칸은 이 연산자에 붙고, eri의 "둘 다 머물 때" 칸은 ZiZj에 붙습니다. 문서 4의 "대각 쿨롱 층 = ZZ 위상"이 바로 이것입니다.

4. Z 사슬: 부호 문제

전자는 페르미온이라 두 전자의 자리를 바꾸면 상태에 −1이 붙습니다. 큐비트에는 이런 성질이 없으므로, 전자를 옮기는 연산에 "지나치는 큐비트마다 Z를 하나씩" 끼워 넣어 부호를 맞춥니다. 이 Z 사슬이 Jordan–Wigner 변환의 유일한 복잡함입니다.

from qiskit_nature.second_q.operators import FermionicOp
from qiskit_nature.second_q.mappers import JordanWignerMapper
hop = FermionicOp({"+_2 -_0": 1.0}, num_spin_orbitals=4)   # 큐비트 0 → 2
print(JordanWignerMapper().map(hop))
# SparsePauliOp(['IXZY', 'IXZX', 'IYZY', 'IYZX'], coeffs=[0.25j, 0.25, 0.25, -0.25j])

5. 해밀토니안 전체를 바꾸면

hcore·eri의 모든 칸을 이렇게 바꿔 더하면 큐비트 해밀토니안이 됩니다. 파울리 문자열(I, X, Y, Z를 큐비트 수만큼 이어 쓴 것)에 계수가 붙은 긴 합입니다.

분자궤도큐비트전자 연산 항파울리 항
H₂ (sto-3g)24—15
N₂ (활성 8궤도)8163,2881,177
from qiskit_nature.second_q.hamiltonians import ElectronicEnergy
ham = ElectronicEnergy.from_raw_integrals(hcore, eri)        # 문서 1의 두 표
qubit_op = JordanWignerMapper().map(ham.second_q_op())      # SparsePauliOp, 1177항, 16큐비트

H₂의 15항은 전부 적어 볼 수 있습니다. IIIZ, IIZI, …(점유 수), IIZZ, …(둘 다 머물 때), XXYY, YYXX, …(두 전자가 동시에 자리를 바꾸는 항). N₂의 1,177항도 같은 세 종류입니다. 항 수는 궤도 수의 4제곱 정도로 늘어나므로 36궤도면 수십만 항이 됩니다.

6. SQD에서 이 변환이 있는 자리

중요한 사실: SQD의 페르미온 경로(fermion.py)는 이 변환을 쓰지 않습니다. 비트열을 배치로 읽고 hcore·eri를 PySCF에 그대로 넘기므로, 파울리 문자열이 등장할 일이 없습니다. 변환이 필요한 곳은 두 군데입니다.

어디무엇을 위해누가 처리
양자 회로 (문서 4)궤도 회전과 쿨롱 층을 큐비트 게이트로ffsim이 내부적으로
qubit.py (문서 6의 7번째 모듈)분자가 아닌 일반 큐비트 해밀토니안(SparsePauliOp)을 비트열 부분공간에 투영해 풀 때사용자가 qiskit-nature 등으로 만들어 넘김

즉 분자 계산만 한다면 Jordan–Wigner를 직접 다룰 일은 없고, 비트열 규약이 왜 그 모양인지만 알면 됩니다. 스핀 모형이나 격자 모형처럼 처음부터 큐비트로 정의된 문제를 SQD로 풀 때 qubit.solve_qubit과 함께 이 변환이 전면에 나옵니다.

전체 코드

from pyscf import gto, scf, mcscf, ao2mo
from qiskit_nature.second_q.hamiltonians import ElectronicEnergy
from qiskit_nature.second_q.operators import FermionicOp
from qiskit_nature.second_q.mappers import JordanWignerMapper

# N₂ 활성 공간 적분 (문서 1)
mol = gto.M(atom="N 0 0 0; N 0 0 1.098", basis="cc-pvdz")
mf = scf.RHF(mol).run()
cas = mcscf.CASCI(mf, 8, (5, 5))
hcore, ecore = cas.get_h1eff()
eri = ao2mo.restore(1, cas.get_h2eff(), 8)

# 전자 연산자 → 큐비트 연산자
fermionic = ElectronicEnergy.from_raw_integrals(hcore, eri).second_q_op()
qubit_op = JordanWignerMapper().map(fermionic)
print(len(fermionic), len(qubit_op), qubit_op.num_qubits)   # 3288 1177 16

# 이동 연산 하나만 보기
hop = FermionicOp({"+_2 -_0": 1.0}, num_spin_orbitals=4)
print(JordanWignerMapper().map(hop))

# 이 큐비트 연산자를 SQD의 큐비트 경로로 풀 때 (분자에는 보통 불필요)

마무리: 이 문서에서 가져갈 것

  • 스핀 궤도 1개 = 큐비트 1개. 점유 1 = |1⟩. 비트열 규약은 큐비트 번호 매기기(α 0~7, β 8~15)와 Qiskit의 출력 순서에서 나온다.
  • "전자 수 세기"는 Z 하나, "둘이 머물 때 밀어냄"은 ZZ. 그래서 회로의 쿨롱 층이 ZZ 위상이다.
  • 전자를 옮기는 연산에는 Z 사슬이 붙는다. 이것이 페르미온 부호를 흉내 내는 장치이고 JW의 유일한 복잡함이다.
  • N₂ 8궤도 해밀토니안은 16큐비트 파울리 항 1,177개. 큐비트 공간 65,536 중 유효 배치는 3,136개.
  • SQD의 분자 경로는 이 변환을 쓰지 않는다. 회로(ffsim 내부)와 qubit.py(일반 큐비트 문제)에서만 등장한다.
